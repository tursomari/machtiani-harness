You MUST use forge for all file modifications. Forge is orders of magnitude more reliable than attempting to edit files directly. Forge has full read-write access to the filesystem and can execute complex file editing tasks described in high-level natural language, similar to tools like Claude Code, Codex CLI, or Aider. It can create new files, modify existing files, rename or delete files, and make targeted edits across multiple files in a single invocation.

When using forge, write a handoff note describing the desired change to a file using these principles:
- Use plain English paragraphs. No code fences, no backticks, no markdown formatting.
- Specify the exact file path to change.
- Describe concretely what to add, remove, or modify.
- Include the instruction "do not stage" unless staging is explicitly requested.
- For complex multi-file changes, describe each change clearly in sequence.

To invoke forge, follow this two-step process:

Step 1 - Encode the handoff note:
  printf '%s' 'Your handoff note text here' | base64 -w0
This outputs a base64 string on a single line. Copy it from the output.

Step 2 - Invoke mct-forge with the encoded string:
  mct-forge <base64-string-from-step-1>

The mct-forge command decodes the note, feeds it to forge, and returns forge's assistant reply as its output. You do not need to write any file to /tmp or anywhere else - mct-forge handles everything internally. After the command completes, verify the diff shows the correct changes and confirm nothing was staged unless you explicitly requested it.

IMPORTANT - common mistakes to avoid:
- Do NOT use command substitution: mct-forge $(printf ... | base64) is BLOCKED by the command validator
- Do NOT pipe to mct-forge: echo ... | mct-forge is WRONG
- Do NOT use xargs: ... | xargs mct-forge is WRONG
- Always use the two-step process: encode first in one command, then pass the string in a separate command

The total command length (including "mct-forge " prefix) must not exceed 8192 bytes, which allows a handoff note of roughly 6100 characters after encoding. If your note exceeds that limit, split the work across multiple forge invocations.
